# Handoff

Notes for whoever picks this project up next, human or agent. This file covers how to work on the project; [EXPERIMENTS.md](EXPERIMENTS.md) records what has been tried and what it showed.

## What it is

gpu-regexp turns an English description ("three digits followed by a dash") into a regex. It has two stages:

1. **Tagger.** A tiny model (44,140 int6 weights) labels each word with one of 28 roles. It is a ScanTagger: hashed sparse features (word, skeleton, prefix, suffix, shape, length), two gated bidirectional scan layers, a 5-tap convolution, and a head with a sentence-mean pool.
2. **Compiler.** A deterministic compiler, `web/compile.js`, turns those roles into a regex. `source === null` means the tool refused, because the text doesn't ask for a pattern.

The tagger runs in the browser on WebGPU or the CPU (`web/gpu-regexp.js`). The demo is on GitHub Pages, which deploys on pushes to `main` that touch `web/**`, so **anything pushed to `web/` on main ships**. Run experiments on branches or worktrees, and cherry-pick to main only after the frozen check.

Training data is generated by `train/grammar.py`. On top of that come:

- `train/negatives.py`: refusal examples, including book prose from `train/prose.txt`
- `train/real_labels.jsonl`: 226 real StructuredRegex descriptions, labelled by search over denotations in `train/label_real.mjs`

## How to run an experiment

Rules that matter:

- Pick seeds on dev and score frozen sets **once**, for the final model, with `SCORE_TEST=1`.
- Compare runs with `eval/compare.mjs`, which does a paired sign test. Report Wilson CIs.
- Run at least 2 seeds. A one-seed gain has fooled us before (E12).

Training runs on the GPU box, reached as `ssh machine`, with a checkout at `~/projects/gpu-regexp` and a venv at `train/.venv`:

```sh
ssh machine 'pgrep -x cs2 >/dev/null && { echo "cs2 running, not starting"; exit 1; }
  cd ~/projects/gpu-regexp && git pull -q &&
  nohup scripts/run_experiment.sh E14-s1 <commit> 1 > /tmp/E14-s1.log 2>&1 &'
```

- **GPU guard:** the box is also used for games. If `cs2` is running, don't use the GPU, and kill the run if it starts mid-run. The command has to abort on its own; printing a warning isn't enough.
- `run_experiment.sh` trains the commit in its own worktree (`../gpu-regexp-exp/<name>`). It then exports the model, checks round trip and parity, scores dev, StructuredRegex dev and refusal dev, and writes `results/<name>.*.json` and `results/<name>.pt`. Options: `STEPS`, `WORKERS`, `SCORE_TEST=1`, and `TRAIN_ARGS="--layers N --d N --ablate conv,..."`.
- **Getting results back:**
  - Copy the JSONs from `machine:~/projects/gpu-regexp/results/` with `scp`, and commit them. Checkpoints (`*.pt`) are gitignored.
  - The box's checkout can collect untracked result files that block `git pull`. Delete only files that are byte-identical to `origin/main`.
- **Shipping a model:**
  1. Run `train/export.py results/<name>.pt`.
  2. Check that `node eval/roundtrip.mjs 3` reports 100% and `node eval/parity.mjs` reports OK.
  3. Copy `web/model.*` to the box and run `node eval/native-gpu.mjs` there. It must show 0 role differences on the real GPU.
  4. Push `web/` to main, then confirm the live files by md5.
- External data:
  - `eval/external/streg/` (StructuredRegex) isn't committed. Copy it next to each worktree; the scripts already do this.
  - `eval/refuse-prose-test.txt` is frozen: score it, never print it.

## Role of EXPERIMENTS.md

EXPERIMENTS.md is the lab notebook. Each round records its question, method, results with CIs, the decision, and whether the change shipped. "Next" holds the plan, and "Reproduce" has a command for every result. Update it with every round. The tone is teaching: the experiments double as ML lessons for Max.

Max also keeps a status note (done / now / next / waiting on Max) and a copy of the log in an Obsidian vault, under `projects/gpu-regexp/`. Keep both current.

## Working with Max

- Start with the one thing to decide or do. Keep messages to at most 5 bullets, one topic at a time, and give a recommendation rather than options.
- Each round needs Max's "go" before it starts. Shipping a model to `web/` needs a separate "yes" after the frozen numbers are in.
- Keep personal details and conversation content out of the repo, including code, tests, data and commit messages.
- Commits end with Co-Authored-By and Claude-Session trailers.
